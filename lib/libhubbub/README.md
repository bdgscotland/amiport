# lib/libhubbub

NetSurf HTML5 tokeniser and tree builder. Reads HTML byte streams,
emits tokens (start/end tags, doctype, comments, characters), and
constructs the DOM via caller-supplied tree-handler callbacks.

Upstream: https://github.com/netsurf-browser/libhubbub @ commit
`6651b8c` (v0.3.8). Copyright 2009-2020 J-M Bell + Daniel Silverstone,
MIT-licensed (see `COPYING`).

## What it is

LibHubbub implements the WHATWG HTML5 parsing algorithm — the
state-machine tokeniser plus the 21-mode tree-construction algorithm.
It is the third lib in the NetSurf-Vampire dep stack and the first
that does meaningful CPU work per input byte.

Subsystems:
- `src/charset/detect.c` — charset autodetection (BOM heuristics + meta tag scan)
- `src/parser.c` — top-level glue (tokeniser + treebuilder coordinator)
- `src/tokeniser/tokeniser.c` (~3450 LOC, 70+ states) — HTML5 tokeniser state machine
- `src/tokeniser/entities.{c,h,inc}` — bsearch over the ~2000 HTML named entity table (`entities.inc` is committed pre-generated; regenerate via `perl build/make-entities.pl` if HTML5 entities ever change)
- `src/treebuilder/` — tree-construction state machine, 21 mode-specific .c files (`after_after_body`, `in_body`, `in_caption`, etc.) + `treebuilder.c` top-level + `element-type.{c,h,gperf}` element-name lookup (gperf-generated `autogenerated-element-type.c` is committed)
- `src/utils/` — error helpers, string ops

## Public API

See `include/hubbub/`:

- `hubbub.h` — aggregator header
- `errors.h` — `hubbub_error` enum
- `types.h` — `hubbub_token`, `hubbub_string`, `hubbub_tag`, etc.
- `functypes.h` — `hubbub_token_handler`, `hubbub_error_handler` callbacks
- `parser.h` — `hubbub_parser_create/destroy/setopt/parse_chunk/insert_chunk/completed/read_charset`
- `tree.h` — full `hubbub_tree_handler` callback set (17 callbacks: create/ref/unref node, append/insert/remove children, clone, reparent, get_parent, has_children, form_associate, add_attributes, set_quirks_mode, encoding_change, complete_script, change_charset)

## Build

```bash
make -C lib/libhubbub
```

Produces `libhubbub.a` (~312 KB). 30 .c files compile clean with zero
warnings.

**CPU target:** `-m68040 -m68881`. Same NetSurf-Vampire dep stack
convention as the other dep libs. See `lib/libwapcaplet/Makefile`
header for the rationale.

**Defines:** `-DNDEBUG` (strips assert and verbose-debug fprintf paths)
+ `-D_DEFAULT_SOURCE` (matches upstream Makefile).

**Depends on libparserutils** (also shipped this branch). Link with
`-lhubbub -lparserutils`.

## Pre-generated files (committed, not regenerated at build)

- `src/tokeniser/entities.inc` — generated by `perl build/make-entities.pl`
  from upstream `build/Entities`. 11647 lines. The HTML5 named entity
  table; bsearch'd by `entities_search_step`. Re-generate from a fresh
  upstream clone if the entity list ever needs refreshing.
- `src/treebuilder/autogenerated-element-type.c` — generated by
  `gperf src/treebuilder/element-type.gperf`. 705 lines. Perfect-hash
  lookup for HTML element names → element-type enum. Re-generate via
  `gperf` (Apple-provided in `/usr/bin/gperf` on macOS, common on Linux)
  if the element list ever changes.

## Test

```bash
make -C tests/libhubbub run
```

Runs 20 tests via `vamos -C 68040 -s 4096 -m 8192 ./test_libhubbub`.
Coverage:
- 6 parser lifecycle tests (create with various charsets / NULL params,
  setopt for token-handler + pause)
- 10 HTML tokenisation tests (text, tag, doctype, comment, self-closing,
  attribute, nested tags, named + numeric entities, chunked input)
- 1 tokeniser-via-parser indirection test
- 2 stress tests (realistic page, byte-by-byte chunked feed)
- 1 Amiga-specific (50-iteration parser create/destroy)

The tree-builder subsystem (21 mode-specific files, ~5K LOC) is
**not** unit-tested in isolation — testing it requires implementing
the full 17-callback `hubbub_tree_handler` interface as a fake. Coverage
of that subsystem comes from upstream's JSON-based test corpus
(json-c-driven, not portable to vamos) plus end-to-end NetSurf parsing
on real-world pages.

## Critical: vamos resource sizing

libhubbub test binaries need **at least 512 KB** for both `__stack`
and `__MEMORY_STEP`. Smaller values (e.g., 256 KB which is sufficient
for libwapcaplet/libparserutils) cause libnix's stdio init to fail
with an Illegal Instruction crash before `main()` runs. This is
because libhubbub references many libnix internals (printf for testing,
the full stdio + malloc + libnix-init chain) and the linked binary's
larger global-data area pushes libnix's startup-time allocation
requirement past 256 KB. Set `__stack = 524288` and
`__MEMORY_STEP = 524288` in any test or consumer that links libhubbub.

## AmigaOS exit cleanup

libhubbub itself does NOT keep process-wide global state (per
source-analyzer audit, the library is fully reentrant). All state
lives in caller-owned `hubbub_parser` instances. Calling
`hubbub_parser_destroy()` on every successfully-created parser is
sufficient.

The library does NOT free the underlying libparserutils inputstream/
codecs it creates internally — those are owned by the parser and
cleaned up by `hubbub_parser_destroy`.

## Tree-handler callback ownership

Per the public API contract (see `include/hubbub/tree.h`):

- All `hubbub_string` data passed to tree-handler callbacks (tag names,
  attribute names/values, text content, comment content) is **library-
  owned and only valid for the duration of the callback**. Consumers
  that need to retain strings must copy them (typically via
  `lwc_intern_string()` from libwapcaplet — that's the canonical
  NetSurf pattern).
- Nodes returned from create_* callbacks must have refcount 1 on
  return.
- The library calls `ref_node` / `unref_node` on consumer-supplied
  nodes to manage lifetime — consumer is responsible for the actual
  ref-count semantics.

## Test ASSERT-failure leak caveat

Same as the prior dep-stack libs: the test framework's `ASSERT_*`
macros early-return without running cleanup. Acceptable for unit-test
purposes (vamos host process exit reclaims memory) but not
representative of a real-world consumer leak.
