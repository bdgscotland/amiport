# lib/libcss

NetSurf libcss -- C implementation of the W3C CSS Cascading Style Sheets
specification (parser, selector matcher, value cascade, computed-style
arena).

Upstream: https://github.com/netsurf-browser/libcss @ commit `104d87f`
(v0.9.x). Copyright 2007-2021 J-M Bell + Vincent Sanders + others, MIT-
licensed (see `COPYING`).

## What it is

LibCSS provides:

- CSS tokeniser (`src/lex/lex.c`)
- Top-level CSS parser (`src/parse/parse.c`) plus 38 hand-written +
  119 autogenerated per-property parsers (~157 .c files in total under
  `src/parse/properties/`)
- Selector matcher (`src/select/select.c`)
- Per-property cascade dispatchers (`src/select/properties/*.c`, ~100 files)
- Computed-style arena allocator (`src/select/arena.c`)
- CSS calc() evaluator (`src/select/calc.c`)
- @charset + BOM detection (`src/charset/detect.c`)
- Stylesheet lifecycle API (`src/stylesheet.c`)

It is the fifth library shipped in the NetSurf Vampire Phase 1 dep stack
(Phase D-prime). Sibling to libdom in Wave 2 -- the two together provide
the DOM + CSS layer that NetSurf's renderer cascades against.

## Critical design fact: 22:10 fixed-point integer math

libcss uses `css_fixed = int32_t` (22:10 fixed-point) for ALL CSS values
(em, px, %, etc.). NO floating-point. The `FLTTOFIX(0.9)` style macros in
property parsers are compile-time constants and fold to integer literals
under -O0. Verified at Stage 7 perf audit: zero soft-float pulls
(`__divsf3`/`__floatunsisf`/etc.) in the final libcss.a.

Implication: downstream consumers are NOT exposed to the FS-UAE
mathieeesingbas crash family (crash-patterns #2 variant) when using
libcss. This is a deliberate libcss design choice that aligns perfectly
with our amiport softfloat-avoidance discipline.

## Public API

See `include/libcss/`:

- `libcss/libcss.h` -- aggregator header
- `libcss/types.h` -- `css_fixed`, `css_unit`, `css_color`, enums
- `libcss/errors.h` -- `css_error` enum (CSS_OK / CSS_NOMEM / CSS_BADPARM
  / CSS_INVALID / CSS_NEEDDATA / CSS_BADCHARSET / CSS_EOF /
  CSS_IMPORTS_PENDING / CSS_PROPERTY_NOT_SET)
- `libcss/stylesheet.h` -- `css_stylesheet_create` /
  `css_stylesheet_append_data` / `css_stylesheet_data_done` /
  `css_stylesheet_destroy` + accessors (get_url, get_title,
  get_language_level, size, quirks_allowed)
- `libcss/select.h` -- `css_select_ctx_create` /
  `css_select_ctx_append_sheet` / `css_select_style` (the cascade entry)
  + `css_select_handler` callback struct (DOM traversal -- consumer must
  implement the ~30 callbacks)
- `libcss/computed.h` -- per-property accessors on a computed style
  (e.g. `css_computed_color`, `css_computed_font_size`, ...)
- `libcss/properties.h` -- the property enum + value enums per property
- `libcss/font_face.h` -- @font-face descriptors
- `libcss/fpmath.h` -- the 22:10 fixed-point macros (FIX, FIXTOINT,
  FDIV, FMUL, etc.)
- `libcss/hint.h`, `libcss/unit.h`, `libcss/functypes.h` -- supporting
  declarations

## Build

```bash
make -C lib/libcss
```

Produces `libcss.a` (~476 KB at `-O0`; size after Stage 7 -O1 promotion
in PERF-REPORT.md).

**CPU target:** `-m68040 -m68881`. Same NetSurf-Vampire dep stack
convention as the prior libs.

**Defines:** `-DNDEBUG -D_DEFAULT_SOURCE -std=c99`.

**Optimization:** see `lib/libcss/PERF-REPORT.md` for the Stage 7 audit
and the final whole-archive vs per-file decision.

**Depends on:** `lib/libwapcaplet/` (interned property strings + values),
`lib/libparserutils/` (lexer input stream + charset codecs). Link order
on consumer side: `-lcss -lwapcaplet -lparserutils`.

## Two source files excluded from the archive

1. **`src/parse/properties/css_property_parser_gen.c`** -- a build-time
   tool with `int main()`, NOT a library function. We pre-generated all
   119 `autogenerated_<PROP>.c` files using this tool ONCE (committed
   to the tree) so the build doesn't depend on a host C compiler at
   library-build time. To re-generate after upstream merge of new
   properties.gen entries:

   ```bash
   cc -o /tmp/gen_parser src/parse/properties/css_property_parser_gen.c
   for prop in $(perl -ne 'print "$1\n" if /^([^#][^:]+):/' \
                   src/parse/properties/properties.gen); do
     line=$(grep "^${prop}:" src/parse/properties/properties.gen)
     /tmp/gen_parser -o src/parse/properties/autogenerated_${prop}.c "$line"
   done
   ```

2. **`src/select/format_list_style.c`** -- 67 lines of UTF-8 (Georgian /
   Armenian / Greek alphabet tables for CSS list-style-type counter
   formatting). bebbo-gcc preprocessor silently corrupts code surrounding
   multi-byte UTF-8 characters (per `.claude/rules/known-pitfalls.md`
   "UTF-8 Characters in Comments Break bebbo-gcc Preprocessor"). NetSurf
   rendering of MVP HTML+CSS does NOT need exotic counter styles -- only
   the rest of the cascade. Re-enable later by ASCII-stripping the
   symbol tables or hex-escaping the codepoints.

   Functional consequence: `list-style-type: georgian` (and ~12 other
   exotic counter styles) are not supported; common values (decimal,
   disc, circle, square, lower-alpha, upper-alpha, lower-roman,
   upper-roman) work fine because they're in `src/select/properties/list_style_type.c`
   which IS included.

## Test

```bash
make -C tests/libcss run
```

Runs the 38-test suite via `vamos -C 68040 -s 4096 -m 8192 ./test_libcss`.
Coverage:

- 8 functional (stylesheet create/destroy + parse simple rule + accessors
  for url/title/language_level/size; select_ctx create/destroy/count)
- 5 error path (NULL params, NULL result, invalid params_version,
  NULL data buffer, NULL ctx)
- 6 edge case (empty stylesheet, comment-only, chunked append,
  multi-selector rule, multi-rule stylesheet, invalid CSS no-crash)
- 5 Amiga-specific (css_error_to_string safe, parse with lengths
  doesn't pull soft-float at runtime, deep nested selectors safe within
  1 MB stack, stylesheet destroy 10x clean, select_ctx_append_sheet)
- 8 stress (50-iter parse+destroy, 1KB CSS, 4KB CSS, long selector
  chain, 50-properties-per-rule, 10-sheet select_ctx, quirks mode,
  inline style)
- 6 property parsing variety (color hex, color named+rgb+rgba, length
  units, margin shorthand, font shorthand, pseudo-classes + descendant)

## Critical: vamos resource sizing

Same as libdom-class: test binaries linking the libcss + libwapcaplet +
libparserutils stack need `__stack >= 1048576` AND `__MEMORY_STEP >= 1048576`.
512 KB cookies are NOT sufficient. Per the existing
`feedback_libnix_stack_scales_with_binary` pitfall.

Apply in test source:
```c
long __stack = 1048576;
unsigned long __MEMORY_STEP = 1048576;
```

## AmigaOS exit cleanup

libcss does not maintain a process-wide global lazy-init table the way
libdom (`dom_namespaces[]`) and libwapcaplet (`lwc_context`) do. All
state lives in caller-owned `css_stylesheet` / `css_select_ctx`
instances.

The downstream `ports/netsurf/` consumer MUST:

1. Call `css_stylesheet_destroy(sheet)` for every stylesheet at exit.
2. Call `css_select_ctx_destroy(ctx)` for every select context at exit.
3. Continue to call `lwc_iterate_strings(NULL, NULL)` -- libcss interns
   property strings via libwapcaplet, so the libwapcaplet cleanup hook
   covers libcss's interned strings transitively.

AmigaOS `-noixemul` does NOT reclaim process memory on exit.

## Test ASSERT-failure leak caveat

Same as the prior dep-stack libs: the test framework's `ASSERT_*` macros
return early from a failing test without running cleanup. Acceptable for
unit-test purposes (vamos host process exit reclaims memory) but not
representative of a real-world consumer leak.

## Consumers

- `ports/netsurf/` (Phase 1 final consumer) -- the cascade engine
- (future) `lib/libsvgtiny/` -- SVG can use CSS for styling

## What NetSurf will need to do

1. Build a `css_select_handler` callback struct against libdom (the DOM
   traversal API libcss needs). The handler must implement ~30 callbacks
   (parent_node, named_ancestor_node, named_parent_node, named_sibling,
   sibling_count, named_generic_sibling, named_property_node,
   text_content, first_child, etc.).
2. Wire `css_stylesheet_create` + `css_stylesheet_append_data` +
   `css_stylesheet_data_done` to the network/file fetch pipeline.
3. Build a `css_select_ctx`, append all stylesheets, and call
   `css_select_style(ctx, doc_node, ...)` for every DOM element during
   layout.
4. Read computed values from the result via `css_computed_*` accessors
   (`css_computed_color`, `css_computed_font_size`, etc.).
5. Free every stylesheet + context at exit per the cleanup discipline above.
