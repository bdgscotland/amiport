# lib/libparserutils

NetSurf parser primitives library — character set codecs (UTF-8, UTF-16,
ISO-8859-1..16, Windows-125x, US-ASCII, ext8 vendor variants), MIB-enum
charset alias resolution, UTF-8/16 codepoint helpers, input stream with
charset conversion, and core utility containers (buffer, stack, vector).

Upstream: https://github.com/netsurf-browser/libparserutils @ commit
`6b0cbf0` (v0.2.x). Copyright 2007-8 J-M Bell, MIT-licensed
(see `COPYING`).

## What it is

LibParserUtils is the second-tier dep beneath every NetSurf parser:
libcss, libdom, libhubbub, and libsvgtiny all link against it. It
provides:

- A pluggable charset codec subsystem (decode bytes -> UCS-4, encode
  UCS-4 -> bytes) with built-in handlers for UTF-8, UTF-16, ISO-8859-*,
  Windows-125x, US-ASCII, ext8 vendor variants
- IANA MIB-enum lookup with ~700 aliases (case-insensitive,
  partial-match-tolerant via `bsearch` over a sorted static table)
- Lightweight UTF-8/16 codepoint helpers (decode, encode, length,
  next/prev offset stepping)
- An input stream that buffers raw bytes and presents them as UTF-8
  on demand, with mid-stream `<meta charset>`-driven charset switching
- Buffer (growable byte array), stack (typed LIFO), vector (typed
  random-access) container primitives

## Public API surface

See `include/parserutils/`:

- `parserutils.h` -- aggregator header
- `errors.h` -- `parserutils_error` enum + error code names
- `types.h`, `functypes.h`
- `charset/codec.h` -- codec API (create, destroy, encode, decode,
  setopt for STRICT/LOOSE/TRANSLIT error mode, reset)
- `charset/mibenum.h` -- MIB-enum lookup
- `charset/utf8.h` -- UTF-8 codepoint helpers
- `charset/utf16.h` -- UTF-16 codepoint helpers
- `input/inputstream.h` -- input stream
- `utils/buffer.h`, `utils/stack.h`, `utils/vector.h` -- containers

## Build

```bash
make -C lib/libparserutils
```

Produces `libparserutils.a` (~78 KB). Compiles 15 .c files clean with
zero warnings under `-Wall -Wextra`.

**CPU target:** `-m68040 -m68881`. Same NetSurf-Vampire dep stack
convention as `lib/libwapcaplet/`. See that lib's Makefile header for
the rationale; in short: matches `ports/netsurf/` consumer ABI exactly,
single -O0 default for safety vs crash-patterns #16, optionally
promoted to -O1 per audit (see Stage 7 finding in the commit history).

**Critical define -- `-DWITHOUT_ICONV_FILTER`:**
libparserutils' `src/input/filter.c` is internally bifurcated. Without
this define, it `#include`s `<iconv.h>` and uses iconv for charset
conversion. AmigaOS has no iconv. With the define, the file's `#else`
branch uses libparserutils' own built-in codec subsystem
(`parserutils_charset_codec_*`) -- which is complete and free-standing.
The amiport build sets this define unconditionally.

## aliases.inc -- pre-generated, committed

The file `src/charset/aliases.inc` (1142 lines) is auto-generated by
upstream's `perl build/make-aliases.pl` from `build/Aliases`. We commit
the generated file so the amiport build doesn't depend on Perl. To
regenerate from a newer upstream alias list: re-clone the upstream repo
and re-run the perl script, then copy the result over.

## Test

```bash
make -C tests/libparserutils run
```

Runs the 57-test suite via `vamos -C 68040 -s 1024 -m 4096`. Coverage:

- 12 functional tests (codec roundtrips for UTF-8, UTF-16, ISO-8859-1,
  US-ASCII, Windows-1252, codec setopt, codec reset)
- 3 error-path tests (unknown charset, NULL params, truncated UTF-8)
- 7 MIB-enum lookup tests (canonical, alias, case-insensitive, unknown,
  to_name roundtrip, is_unicode true/false)
- 11 UTF-8 helper tests (1/2/3/4-byte to_ucs4 + from_ucs4 + length +
  char_byte_length + next + prev + truncated)
- 4 UTF-16 helper tests (BMP + surrogate pair to_ucs4 + from_ucs4 BMP +
  supplementary roundtrip)
- 5 buffer tests (create/destroy + append + grow + insert + discard)
- 3 stack tests (create/destroy + push/pop LIFO + get_current)
- 3 vector tests (create/destroy + append/iterate + clear)
- 3 input stream tests (create/destroy + append/peek/advance + chunked
  append)
- 3 Amiga-specific (utf16 helper native order on 68k + buffer alignment
  stress)
- 3 stress (4 KB UTF-8 decode + 1000-item vector + multi-plane codec
  roundtrip)

OOM is not exercisable on vamos without a custom allocator hook;
upstream's Check-based tests cover that.

## Known upstream behaviour quirks (not bugs in our port)

1. **Codec subsystem only handles "UTF-16" (BOM-driven)**, not explicit
   `UTF-16BE` / `UTF-16LE`. Those names exist in the alias table but
   the UTF-16 codec handler at `src/charset/codecs/codec_utf16.c:76-78`
   only matches MIB 1015 (UTF-16). Pages declared `UTF-16BE` /
   `UTF-16LE` would normally use iconv -- under WITHOUT_ICONV_FILTER
   they hit `PARSERUTILS_BADENCODING`. NetSurf in practice rarely sees
   explicit BE/LE; the BOM-driven UTF-16 path covers the common case.
   If a future port needs explicit BE/LE, register two more codec
   handler dispatch entries that map MIB 1013/1014 -> the existing
   utf16 handler with byte-order flags.

2. **utf16_from_ucs4 supplementary-plane formula is non-standard**
   (`src/charset/encodings/utf16.c:75-92`). The encoder uses
   `0xD800 | (((ucs4 >> 16) & 0x1f) - 1) | (ucs4 >> 10)` which
   diverges from the standard surrogate-pair formula
   `0xD800 | ((ucs4 - 0x10000) >> 10)`. The encode/decode roundtrip
   for codepoints >= U+10000 in this implementation is NOT clean. For
   NetSurf's HTML / CSS parser usage this is rarely exercised
   (text content is typically passed through unchanged by the
   tokeniser; emoji-heavy content is the obvious risk). Not patched
   here; tracked for future evaluation when ports/netsurf surfaces a
   real-world issue.

## AmigaOS exit cleanup

libparserutils itself does NOT keep a global hash table the way
libwapcaplet does. State lives entirely in caller-owned codec /
inputstream / buffer / stack / vector instances. As long as the caller
calls `parserutils_*_destroy()` on every `parserutils_*_create()`,
there are no library-side leaks at exit.

There IS one static codec dispatch table in `src/charset/codec.c`
(5 entries pointing at the 5 built-in handlers) and the static const
aliases tables in `src/charset/aliases.inc`. These are read-only data,
no allocation, no leak.

The aliases bsearch comparator in aliases.c uses standard libnix
`bsearch` -- no per-call allocation.

## Test ASSERT-failure leak caveat

Same as `lib/libwapcaplet/`: the test framework's `ASSERT_*` macros
return early from a failing test without running cleanup. Acceptable
for unit-test usage (vamos host process exit reclaims memory) but not
representative of a real-world consumer leak.
