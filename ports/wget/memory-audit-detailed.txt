WGET 1.20.3 — MEMORY SAFETY AUDIT

===== CRITICAL FINDING 1: CLEANUP() IS EFFECTIVELY NO-OP ON PRODUCTION BUILD =====

FILE: ported/src/init.c, lines 1894-2036
ISSUE: The cleanup() function only actually frees allocations when compiled with DEBUG_MALLOC or TESTING flags.

Current compile flags (from Makefile):
- CFLAGS = -std=gnu99 -O2 -noixemul -m68020
- NO DEBUG_MALLOC
- NO TESTING

Code structure:
  cleanup() {
    if (cleaned_up++) return;  /* called from main() at end */
    /* Real cleanup is here: */
    #if defined DEBUG_MALLOC || defined TESTING
      /* 70+ xfree() and cleanup function calls */
    #endif  /* DEBUG_MALLOC || TESTING */
  }

IMPACT: On production AmigaOS build, cleanup() is a no-op. All allocations from the start of the program until exit() are LEAKED permanently.

===== CRITICAL FINDING 2: NO ATEXIT() CLEANUP REGISTERED =====

FILE: ported/src/main.c, lines 1315-1318
ISSUE: amiport_expand_argv() is called WITHOUT atexit() registration.

Code at line 1316:
  amiport_expand_argv (&argc, &argv);

Expected pattern (from known-pitfalls.md):
  amiport_expand_argv (&argc, &argv);
  atexit(cleanup_argv);  /* <-- MISSING */

IMPACT: If ANY error handler (err/errx) exits early, or if exit() is called from nested function, argv expansion memory is leaked permanently.

===== CRITICAL FINDING 3: program_argstring LEAK =====

FILE: ported/src/main.c, lines 1344-1361
ISSUE: malloc'd argstring never freed.

Code:
  program_argstring = p = malloc (argstring_length);  /* line 1344 */
  if (p == NULL) {
    fprintf (stderr, _("Memory allocation problem\n"));
    exit (WGET_EXIT_PARSE_ERROR);  /* <-- LEAKS on allocation failure */
  }
  /* ... populate buffer ... */
  *p = '\0';
  /* Never freed in main() */

EXIT PATH: Only freed in cleanup() which doesn't run in production.

IMPACT: ~200-500 bytes per invocation leaked.

===== CRITICAL FINDING 4: home_dir() RETURNS malloc'd COPY =====

FILE: ported/src/init.c, lines 516-567
ISSUE: Function returns xstrdup() copy, caller doesn't track result.

Code at line 563:
  ret = home ? xstrdup (home) : NULL;  /* allocates new string */
  xfree (buf);  /* frees old buf, but not ret */
  return ret;  /* caller gets malloc'd pointer */

Called from main.c line 1365:
  opt.homedir = home_dir();  /* stores pointer globally */

CLEANUP: opt.homedir is freed in cleanup() line 2016, which doesn't run in production.

IMPACT: ~64 bytes per invocation (typical homedir path length).

===== SUMMARY OF LEAKS =====

Tier 1 (GUARANTEED PER INVOCATION):
- program_argstring: 200-500 bytes
- home_dir() result: 64 bytes
- config file paths: 256 bytes (wgetrc_env + wgetrc_user)
- opt.* allocations from initialize(): 1-5 KB

Total Tier 1: ~2-6 KB per invocation

Tier 2 (CONDITIONAL ON FLAGS/CONFIG):
- HSTS store (if opt.hsts): 1-50 KB
- Cookie jar (if cookies): 1-10 KB
- DNS cache (if recursive): 10-100 KB
- HTTP headers cache: varies

Total Tier 2: 10-160 KB depending on usage

WORST CASE: Recursive multi-file download with HSTS and cookies enabled can leak 150+ KB per invocation.

===== UNFIXABLE WITHOUT CODE CHANGES =====

The root cause is the gating of cleanup() on DEBUG_MALLOC/TESTING flags. This is a design decision in upstream wget that assumes either:
1. The program is being debugged/tested with leak detection
2. The OS will clean up process memory on exit

AmigaOS with -noixemul violates assumption #2 — there is NO automatic process cleanup.

===== VERDICT: CANNOT SHIP =====

Leaks exceed acceptable threshold for AmigaOS. Fix required: Must enable DEBUG_MALLOC or TESTING in compilation, OR apply targeted atexit() cleanup pattern for argv + program_argstring, OR accept the leaks as documented limitation.
